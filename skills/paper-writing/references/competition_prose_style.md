# 中文数学建模论文的研究化叙述风格

本参考把严谨研究写作的语言特征转译为中文数学建模竞赛论文。它服务于正文起草、续写和润色，不替代题面、结果注册表、公式协议、官方模板或证据纪律。

## 一、写作目标

让读者不依赖作者的口头说明，也能顺着“题目条件为何产生困难、模型如何回应困难、结果说明什么、结论在何处失效”的链条读下去。文字的价值来自精确事实、清楚关系和诚实边界，不来自华丽形容词或算法堆叠。

每个句子只承担一种主要作用：提出判断、给出依据、解释机制、限定范围，或连接上下文。相邻两句应能说明推进关系；不能说明作用的句子删除、合并或改写。

## 二、可迁移的语言特征

### 逻辑先行，叙述自然

- 每节开头先给领句，说明本节要解决的对象、目标或承接关系，再展开变量、公式、算法和结果。
- 每段围绕一个判断推进：领句提出判断，中段给题面/数据/模型证据，末句给范围、含义或自然转入下一段。不要把内部工作流、检查表和“首先让我们”写进论文。
- 先说明为什么需要该模型，再定义模型；先陈述图表显示的现象，再解释其含义；先说明验证对象和风险，再报告验证结果。
- 同一术语、对象、方案和指标全篇使用同一名称。不要为了避免重复而随意改称，导致读者误以为是不同对象。

### 准确、克制、有边界

- 已经由题面、运行结果和独立验证支持的事实，可以使用“表明、证实、得到”；只由趋势或有限情景支持的判断，使用“提示、说明、与……一致”；超出直接观测的解释，使用“可能反映、或可解释为、仍需进一步验证”。
- “显著”仅用于给出相应统计或工程判据的结果；“最优、首次、唯一、全面、卓越、颠覆性、遥遥领先”等词必须有明确范围和证据，否则删去或改为可验证的事实。
- 不把相关性写成因果，不把可行性写成最优性，不把训练拟合写成泛化，不把单次优势写成稳定改进。
- 主动呈现限制、失败区间和证据不足。限制必须对应真实的不确定来源，而不是礼貌性地补一句“仍有不足”。

### 自包含而不复述

- 首次出现的符号、缩写、数据口径、比较对象和评价指标均给出必要定义；读者不应依靠“上图”“前文”或外部资料猜测。
- 图、表、公式各有分工：图展示关系或趋势，表给精确数值，公式给结构，正文解释判断与边界。不要把三者逐字复述。
- 后续小问采用“继承—新增—替换—修正”写法，只交代变化部分。流程图已表达的步骤不在正文逐条翻译。

## 三、分节叙述契约

| 位置 | 应回答的问题 | 推荐叙述顺序 | 常见失误 |
| --- | --- | --- | --- |
| 问题分析 | 这一问要判断什么，难点为何出现 | 任务与约束→数学转化→模型理由→交付物 | 重复题面、提前堆公式或先报结果 |
| 模型建立 | 各模块分别解决什么困难 | 目标/机制→变量与关系→约束→适用范围 | 只罗列公式、模块与困难无对应 |
| 求解方法 | 为什么该算法能处理该结构 | 求解对象→算法/参数→停止条件→输出 | 软件操作流水账、把算法名称当理由 |
| 结果分析 | 在何种条件下观察到什么 | 指向图表→核心数值→规律→实际解释 | 朗读图例、混入未经验证的机理 |
| 模型检验 | 检验何种风险，能支持什么 | 风险→方法→证据→结论边界 | 用可行性或收敛替代稳健性/泛化 |
| 评价与推广 | 模型在哪些条件下有用或失效 | 具体优势→限制来源→适用条件→可行扩展 | 空泛表扬、无根据的广泛推广 |
| 摘要 | 解决什么、如何解决、得到什么 | 对象与总路线→分问模型/关键结果→总体决策与边界 | 按目录复述、堆算法名、放无来源数字 |

## 四、可直接采用的表达骨架

| 目的 | 建议写法 | 不建议写法 |
| --- | --- | --- |
| 引出模型 | “为同时满足……约束并刻画……关系，构建……模型。” | “为了更好、更全面地解决问题，创新性地建立模型。” |
| 说明机制 | “该项通过……进入目标函数，因此会在……条件下抑制/鼓励……。” | “该设计有效提升了模型性能。” |
| 报告结果 | “见图X，在……范围内，指标由……变化至……，其中……情景最为明显。” | “结果十分显著，模型表现优异。” |
| 解释趋势 | “这一趋势与……约束/数据特征一致；在……条件下，该解释尚需验证。” | “这充分证明了模型的先进性。” |
| 比较方案 | “在相同……情景下，方案A的……较方案B高/低……；配对区间……，因此……” | “方案A全面碾压方案B。” |
| 表达局限 | “当……缺失或……超出当前参数范围时，结论不宜外推。” | “本模型仍有一定局限性。” |
| 承接后问 | “在第一问得到的……基础上，本问新增……，以处理……。” | “接下来继续解决第二问。” |

这些骨架必须填入当前题目的真实对象、条件和证据，不能作为空泛套话直接输出。

## 五、去模板化与润色检查

- 删除空泛开场、营销式形容词、虚假三段并列、机械“首先—其次—最后”、泛化的“通过……从而……”，以及与论证无关的长定语。
- 优先用朴素动词和具体名词：构建、约束、估计、比较、重构、检验、报告、观察、说明；少用“赋能、打造、实现全面提升、充分彰显、具有重要意义”等无信息表达。
- 变换句长，但不要为“自然”牺牲数学关系。长句中同时出现条件、公式、结果和结论时，按论证角色拆开；短句连续时用真实的因果、转折或递进关系连接。
- 润色不得改变数值、符号、因果方向、结论力度、适用范围或负面结果。若调整会触及科学含义，标记为待确认或退回相应责任 Skill。

## 六、交付前自检

1. 删除每段的图表和公式后，领句是否仍能说清该段判断？
2. 每个“因此、说明、表明、证明、显著、最优”之后是否有对应证据及准确边界？
3. 相邻两句、相邻两段是否存在可辨认的承接关系？
4. 是否有空泛表扬、重复小结、内部过程提示、无证据例子或为了避免重复而改变术语？
5. 是否把观察、解释、假设和建议明确区分？

任何一项为否时，先修复论证或证据，再做措辞润色。
