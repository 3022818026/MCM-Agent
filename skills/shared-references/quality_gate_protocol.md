# 质量门禁、严重度与独立复核协议

本文件统一规定数学建模工作中的早停门禁、问题严重度、检查可执行性和修订闭环。它不改变各专项 Skill 的科学标准；具体模型、数据、图表和论文规则仍以规则权威索引指定的来源为准。

## 0. Skill执行握手

每次触发任一通用Skill时，责任Skill必须先完成以下握手，不能只声明“已读取规则”：

1. 按`rule_authority_index.md`完整加载常驻基线和本任务需要的专项权威文件；只激活与当前任务、当前阶段和用户最新要求有关的规则。`paper_writing_revision_contract.md`虽为全程常驻文件，非写作阶段只激活其中对应Skill的论文证据交接责任，不提前生成无证据正文。
2. 在内部建立一张活动规则卡，至少列出：本次职责边界、必须执行、禁止执行、需要用户确认、输出形式、完成证据，以及`paper_writing_revision_contract.md`中本阶段需要形成的论文证据交接。相同规则只保留权威来源的一份，其他文件中的入口不得改写其含义。
3. 冲突按“用户最新明确要求 → 数学与数据正确性 → 官方规则与当前项目证据 → 规则权威来源”解决；无法安全消解时保持阻断并请求最小必要信息。
4. 生成或修改后逐条核对活动规则卡。任何必须项没有可定位证据、禁止项被触发或确认项尚未获准时，必须修复、回退或保持候选状态，不得交付或宣称完成。

活动规则卡默认只用于内部执行和验收，除非用户要求，不把它扩写进论文或最终答复。
## 1. 问题分级

| 级别 | 含义 | 阶段动作 |
| --- | --- | --- |
| 阻断 | 会使题意、数据、数学、结果真实性、匿名、官方格式或交付边界失效的问题 | 立即停止受影响阶段，定位责任 Skill，修复并重新核验下游产物 |
| 高风险 | 不一定立刻失效，但足以改变模型选择、主结论、可比性、可解释性或提交可信度的问题 | 在进入下一阶段或发布前闭环，不得用措辞弱化替代证据 |
| 改进项 | 不改变核心正确性但影响清晰度、效率、可读性或维护性的事项 | 登记后按时间和价值处理，不得伪装成阻断项 |

- 阻断项示例包括：题面或附件缺失/误读、数据泄漏、未运行却写入结果、关键约束未实现、核心数字无来源、错误引用、论文身份泄露、官方硬格式不符。
- 不得因为审美偏好、算法偏好、篇幅习惯或单一 Agent 的主观不适而标记为阻断。

## 2. 门禁设计

每个关键阶段的门禁至少说明：检查对象、核心风险、可观察证据、通过条件、失败动作、责任 Skill、下游影响和复核状态。

| 字段 | 要求 |
| --- | --- |
| 检查类型 | 区分自动可查、可由当前材料人工核查、需用户确认三类 |
| 证据定位 | 指向题面、数据、代码、日志、结果 ID、图表或正文位置 |
| 失败动作 | 指定修复、重算、重绘、重写、补充核验或请求用户决定 |
| 传播范围 | 说明受影响的评价、图表、正文、摘要、附录和发布包 |

- 自动检查只能声明其覆盖的格式、结构或数值关系；不得把脚本通过、文件存在或退出码为零写成数学或事实正确。
- 需要用户确认的事项必须如实标明，例如未知现场事实、外部资料全文含义、官方 AI 披露解释和用户意图。不得将其伪装为已自动验证。
- 每项最终通过的结论至少经历与其核心风险相匹配的独立证据路径；同一代码路径的重复运行不自动构成独立复核。

## 3. 早停与回退

- 先执行能否定路线或结论的高信息量检查，例如输入完整性、单位/量纲、硬约束、泄漏、透明基准、代表性小规模核验、关键反例和最终格式门禁。
- 一旦发现阻断项，停止不相关的调参、扩写、制图或美化；先处理根因。不能用更多候选模型、更多图或更长文字遮蔽反证。
- 若当前数据已反驳核心机制、透明基准已支配主路线、或关键条件无法满足，则将该路线退回“放弃/待重构”，并输出证据和可行替代，而不是继续进行装饰性评分。
- 修复后从最早受影响阶段重新建立证据；保留失败候选和问题台账，不静默覆盖或宣布原方案成功。

## 4. 反向审视与独立性

在路线锁定、评价结论、重要图表、摘要和终审前，至少追问：

1. 若从头审题，是否会改变目标、假设、评价单位或数据划分？
2. 主结论依赖哪些未检验前提；有没有相反证据、反例、失效样本或更简单解释？
3. 结论来自完整证据还是只选择了支持性结果；负面结果、失败区间和比较条件是否已保留？
4. 若删去所有结论性措辞，题面、代码、结果和图表能否独立支持当前说法？

发现反证后按影响处理：推翻则改结论；削弱则增加条件边界；不同但兼容则并列说明；没有可定位反证则不为形式谦虚而无依据弱化。

## 5. 交付问题台账

在评价、写作终审和复杂修订中使用问题台账。每项问题包括：ID、阶段、严重度、直接证据位置、影响范围、修复动作、责任 Skill、复核证据和状态。

- 每个阻断项和高风险项必须有可执行的修复路径；“整体重写”不是充分建议。
- 交付前没有未决阻断项；高风险项要么关闭，要么按用户授权以明确限制交付。
- 对用户的正式论文正文不输出内部门禁清单；审核报告则应优先给阻断项和高风险项，再给改进项。

## 6. 完成门槛

阶段只有在门禁范围、未覆盖风险、证据定位、下游传播、修订状态和需用户确认事项都被如实记录后，才能从候选状态晋级为已核验。

## 7. 全程生成—审查—修复闭环

本节是八个通用Skill在生成数据、设计、代码、结果、图表、论文文字或审核报告时共同执行的强制闭环。专项规则定义检查内容；本节只统一触发时点、状态、修复和发布边界。

### 7.1 生成前门禁

每次开始一个可交付单元前，责任Skill必须从本Skill、当前题目、官方规则和已绑定产物中提取适用验收项，明确输入版本、输出用途、可观察证据、`paper_writing_revision_contract.md`要求的本阶段论文证据交接和下游影响。题面、附件、授权、结果来源或关键规则缺失时，不得用假设、历史案例或模拟结果补齐；将状态标为阻断，并仅请求完成该单元所必需的信息。

### 7.2 生成后审查

每次生成或修改后立即执行适用的自动检查和人工核对，至少覆盖本Skill已规定的正确性、可追溯性、一致性和交付格式要求。检查记录应包含：产物、规则来源、检查项、证据位置、状态、失败动作、责任Skill、受影响下游产物和复核证据。自动脚本、文件存在、退出码为零或视觉直觉均只能证明各自覆盖的范围。

### 7.3 未通过时的修复闭环

任何阻断项或高风险项未通过时，当前单元不得标记为完成。责任Skill应先定位根因和最早受影响检查点，再在用户已授权的范围内修复、重算、重绘、重写或回退；随后重新执行全部受影响检查，并使评价、图表、论文、摘要、附录和发布包等下游产物转为待复核。不得以保留旧数字、弱化措辞、增加装饰性内容或跳过检查掩盖失败。

修复需要新的用户选择、原始附件、官方解释或外部授权时，如实保持阻断并说明最小缺口；阻断不等于通过，也不得虚构“完全满足”。改进项可按用户时间预算处理，但不得掩盖阻断项或高风险项。

### 7.4 发布与独立性

只有全部适用验收项具有可定位的通过证据、传播清单已清零且没有未决阻断或高风险项时，才可以称为已完成、已核验或可提交。同一责任Skill的生成后审查是必要自检，不能替代模型评价或论文独立审核；完整论文仍须由paper-review按独立复核协议终审。

### 7.5 责任路由

数据与划分问题交由data-preparation；题意、路线和假设问题交由modeling-design或modeling-scientist；代码、结果和复现问题交由model-implementation；性能、稳健性和结论边界问题交由model-evaluation；视觉与图表证据问题交由figure-generation；正文、公式、引用和版式问题交由paper-writing；完整交付物的独立终审问题交由paper-review。路由后必须保留问题台账和复核证据，不能只转交而不复查。
