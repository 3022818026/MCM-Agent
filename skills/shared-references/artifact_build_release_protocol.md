# 数学建模产物构建、候选发布与恢复协议

本协议补充 `agent_runtime_protocol.md`，只规定运行模式、环境预检、进程控制、产物构建、候选结果晋级和失败恢复。数据处理、模型选择、模型评价、论文内容和独立终审仍由对应 Skill 决定。

## 一、规则登记与职责归属

- 共享规则应登记规则 ID、适用阶段、责任 Skill、优先级、来源、启用条件、冲突项和最近复核时间。当前题目的字段、参数、阈值和结论不得进入通用规则。
- 数学与数据正确性、附件完整性、结果真实性、匿名和官方格式属于常开门禁；推理强度只能增加比较、复核和诊断深度，不能关闭常开门禁。
- 同一规则只保留一个权威来源。专项 Skill 只引用共享协议，不复制维护相同正文；出现冲突时先按用户最新要求、数学与数据正确性、官方规则和当前项目证据裁决，再更新权威来源。

## 二、运行模式与授权边界

- **诊断模式**只读取和定位问题，不修改代码、数据、论文或结果。
- **设计模式**形成任务链、模型路线和验证协议，不把候选路线写成已经运行的结论。
- **实现模式**仅修改用户明确授权的代码或项目目录，并生成真实运行产物。
- **写作模式**只消费已核验结果；发现结果或模型错误时立即回退，不在文字中补造或修饰。
- **审核模式**先报告证据、影响和责任 Skill；除非用户同时授权修订，否则不直接改动交付物。
- **恢复模式**先比较输入、配置和关键产物哈希，再决定续接位置；不得因为旧会话声称完成就跳过重新读取和复核。

## 三、真实进度、运行台账与错误记录

- 进度状态只使用计划、运行、待复核、已核验、失败、取消和已发布等有证据的状态。不得用计时器伪造百分比，文件存在也不等于任务完成。
- 运行台账记录阶段事件、开始与结束时间、输入哈希、数据/配置/运行 ID、入口命令、环境 ID、受控进程 ID、输出文件、检查结果和状态。
- 日志格式或结果注册表发生结构变化时，登记模式版本，迁移前备份，迁移后验证旧记录仍可读取；不能静默丢弃失败记录。
- 错误报告至少给出错误类别、直接证据、影响范围、是否可安全重试、下一项安全动作和需用户决定的事项。无法精确获得的耗时、资源或用量只能标为估计值。

## 四、环境与依赖预检

- 运行前解析解释器、求解器、GPU、LaTeX 和关键工具的候选路径，记录最终选择及选择理由；验证它们是实际文件且版本满足要求，不只相信“已就绪”标记。
- 保存操作系统、Python/R/Matlab/求解器/LaTeX 版本、关键包精确版本、线程与硬件信息；可行时使用锁文件和包哈希，避免只记录宽松版本范围。
- 检查中文、空格和长路径兼容性。命令使用参数数组或可靠转义，不依赖可能被关闭的 8.3 短路径作为唯一方案。
- 依赖缺失时先报告。离线资源优先，但任何安装、联网下载或镜像切换都必须符合用户授权并完整等待安装结果；不得静默安装、信任未知镜像或把未完成安装判为成功。
- 对图像生成、文档编译、求解器、GPU和专用软件建立能力—替代矩阵。关键交付不得硬依赖单一生态；首选工具不可用时，退回可复现、可审查且不改变结论的程序化或人工核验路线，并记录视觉、性能或功能差异。

## 五、受控进程与取消

- 只登记并管理本次运行创建的子进程和进程树；超时、取消或退出时只终止这些进程，不得按 `python.exe`、求解器或编译器名称清理整台计算机的同名进程。
- 区分总时限、单工具时限和无进展时限。长时间求解应通过日志、迭代计数或心跳证明仍在推进，而不是因为进程存在就无限等待。
- 用户取消后保存已完成日志、失败状态和可恢复检查点，清理本次运行的临时资源，不删除项目外目录或全局会话。

## 六、产物稳定性、新鲜度与引用闭环

- 读取新生成文件前，确认大小和修改时间连续稳定，并执行与文件类型匹配的打开、解析或结构检查；随后登记内容哈希。
- 构建前记录目标文件的时间与哈希。构建成功必须产生新的目标文件，且其来源、运行 ID 和输入版本匹配；不得把残留 PDF、图片、表格或结果文件误判为本次成功产物。
- LaTeX 或其他需要交叉引用的构建按实际需要执行足够轮次，保留完整日志，并检查致命错误、未解析引用、字体替代、溢出、空白页和旧产物回退。编译器退出码为零仍需打开最终文档逐页复核。
- 建立引用资产清单，列出正文引用、实际存在、未引用和缺失的图、表、代码、附录与支撑文件；预览只用于导航，不能替代完整数据和最终版面检查。
- 文件监听和自动刷新必须等待稳定写入。只检测扩展名、文件大小或文件存在不能证明内容正确。

## 七、候选结果晋级与回滚

- 重要数据、模型、结果、图表和论文版本采用“候选—检查中—已确认”三阶段状态。候选产物不得直接覆盖最近的已核验版本。
- 候选版本必须依次通过完整性、科学正确性、结果注册、下游一致性和目标格式渲染检查，才可原子晋级为当前版本；晋级前保留可追溯备份。
- 新版本首次复核失败、运行中断或下游一致性未通过时，恢复最近的已核验版本，同时保留失败候选、日志和问题台账，禁止静默回退后宣称成功。
- 数据口径、模型索引、目标函数、随机流或结果源发生变化时，使受影响的评价、图表、正文、摘要和附录全部转为待复核；只有传播清单清零后才能再次发布。

- 候选产物晋级前必须附有适用的全程生成—审查—修复闭环记录；只要存在未关闭的阻断项或高风险项，候选版本不得发布为已确认版本。
## 八、模板、发布包与隐私卫生

- 模板发布前扫描并删除开发者绝对路径、真实姓名、学校/团队信息、历史题目字段、示例结果、会话 ID、令牌和其他凭据。示例配置使用明确占位符，不把本机路径当默认输入。
- 模板只提供结构与检查点，不强制图数、公式数、模型数、交叉验证折数、清洗方法、流程图节点或固定章节密度。
- 模板、示例和演示项目必须通过其声称适用的当前规则；若为教学简化版，必须显式标注省略项和不可作为最终交付的边界。文档承诺的命令、参数和产物要由实际入口回归验证，发现文档—实现脱节时修正文档或实现，不能只让形式检查继续通过。
- 最终交付只包含当前题目需要且已登记的代码、数据说明、结果、图表、论文和支撑材料；第三方运行库按许可证和竞赛要求说明，不把缓存、虚拟环境、历史构建物和个人元数据塞入提交包。
- 最终构建尽量使用本地、固定版本的字体、样式和渲染依赖；不得依赖临时 CDN、登录状态或未记录的网络资源才能复现版式。

## 九、明确拒绝的实现模式

- 沙箱、权限校验、加密或路径边界失败后继续运行；
- 加密失败后把凭据退化为明文保存；
- 使用字符串前缀代替规范化目录边界检查；
- 通过广泛进程名终止用户其他任务，或删除全局会话和项目外目录；
- 只因文件存在、SDK 返回成功、退出码为零或数值看似合理就标记完成；
- 恢复时禁止重读已经变化的输入，或复用来源不明的旧图、旧表和旧结果；
- 用固定模板数量、固定算法或自动模拟数据制造形式上的完整交付。

## 十、完成标准

当前阶段只有在以下条件同时满足时才能释放：运行模式与授权一致；环境和入口可定位；输入与产物哈希可追溯；受控进程已结束或明确移交；目标产物为本次新生成且可打开；结果及引用资产完成登记；候选版本通过相应科学与版式门禁；失败、估计和未决事项未被隐藏。
