# 通用论文写作要求

## 基本风格与信息唯一归属

以清楚、直接、先解释依据再给模型的表达为基准。每一节、段落、公式、图和表必须增加新信息；无法说明功能的内容删除、合并或移入附录。

同一信息只在最合适位置完整表达一次：

| 信息 | 唯一主要位置 |
| --- | --- |
| 背景、对象、条件与任务 | 问题重述 |
| 数学转化、困难与模型理由 | 问题分析 |
| 共用清洗、参数形成与初步规律 | 数据预处理 |
| 假设及其简化边界 | 模型假设 |
| 集合、参数、变量、目标和约束 | 模型建立 |
| 算法、求解器、参数、停止条件与精度 | 模型求解 |
| 核心数值、规律与实际解释 | 结果分析 |
| 可行性、精度、泛化和稳健性 | 结果验证 |
| 优点、不足、适用边界和推广 | 模型评价 |
| 完整结果、长代码和支撑清单 | 附录与支撑材料 |

不得在“问题分析—总体方法—建模思路”重复同一模型，不在摘要、正文、图、表和结论中完整复制同一组结果。

## 题目、关键词与摘要

- 题目体现研究对象、核心任务与主要机制/模型；贡献来自约束或机理时突出机制，不强行堆算法名，不照抄赛题或使用空泛的“智能、融合、多维”。
- 关键词一般3—6个，覆盖核心模型、算法、机制、主要约束或验证方法；避免“数学建模、Python、数据分析、结果分析”等泛词。
- 摘要在正文和结果锁定后撰写：先用1—2句总括目标与总体路线，再按问题顺序写“数学任务—核心模型—求解方法—关键结果—主要结论”，不写成题目重述，不放公式，不罗列全部指标。
- 官方模板允许时，可适度加粗核心模型、算法、关键指标、最重要数值和最终决策；每问只突出少量关键信息，不加粗连接词或整段文字。
- 所有摘要数字来自结果注册表，并能在正文和表格中定位；避免连续使用“对于”。

## 问题重述、分析与流程图

- “问题重述”作为一级标题时，固定设置“问题背景”和“问题重述”两个二级标题。“问题背景”只交代研究场景、现实矛盾、研究对象与任务价值；“问题重述”压缩题面，提取已知条件、限制、各问任务和最终输出。两节不得相互重复，也不得提前写模型、算法、结果或评价。
- “问题分析”作为一级标题时，按题目小问分别设置“问题一分析”“问题二分析”等二级标题，不把多问混写在一个无区分段落中。每问只说明数学任务、主要困难、拟用模型、选择理由、与前后问关系和交付物；原则上一段，复杂问题最多两段，不提前展开公式、变量清单、算法步骤或结果。
- 各问共享数据或明显递进时，在问题分析末设置总体流程图，只表达数据、共用处理、问题关系、模型递进、输出和总体验证。
- 多阶段处理、多子模型、复杂约束、迭代搜索、情景生成或多步骤验证时，设置单问题流程图；简单问题不机械添加。流程图控制5—10个短节点，与正文不重复。

## 章节结构与标题层级

- 正式写作前先确定一级、二级、必要三级标题，流程图和验证位置、附录内容及页数预算；不边写边无限增加标题。
- 共用数据处理集中成章，单问独有处理留在对应问题。
- 正文原则上不超过三级标题。三级标题仅在至少两个并列子内容均有独立方法/公式/结果且有足够篇幅时使用；单个参数、单张图、短结论、优缺点列表通常不用三级标题。
- 每问形成“目标/依据—模型—求解—结果—验证—解释”闭环，但验证结论可融入结果段，不机械增加重复“小结”。
- 后一问继承前问时采用增量式写法：引用前文公式，只展开新增、替换或修正内容，并比较机制增加前后的结果。

## 公式、结果、图表与正文分工

- 公式前说明建立目的，公式后只解释符号、作用和必要数学意义，不逐字翻译。
- 表格承载精确数值，图形展示趋势、差异、分布、误差或结构，正文解释原因、边界和决策含义；三者完全重复时原则上二选一。
- 结果分析按“核心数值—变化规律—实际解释”组织。正文保留代表性结果，完整年度、样本、矩阵、搜索记录和决策明细进入附录或结果文件。
- 图表必须先在正文引用，再出现；采用“见图X、根据表X、由式（X）”，不用“上图、下表、前面的公式”。
- 每张重要图表后用少量文字指出最重要现象、原因和含义，不朗读图例或所有单元格。

## 精简与篇幅

优先删除重复题意、教材式定义、无证据自评、流程套话、图表复述和重复小结；合并无效标题，把完整结果与长代码移入附录。流程图只替代流程性文字，不能替代核心数学依据。

一个自然段只承担一个主要功能，通常控制在100—250字；超过300字时检查是否混合数据、模型、求解、结果、验证和评价，但不得机械拆成碎片。正文页数以当届官方上限为硬约束，提前分配预算，不使用固定页数覆盖官方要求。

## 候选模型比较与正文边界

- 候选模型比较、调参和淘汰记录属于设计与评价证据，默认保存在内部报告、结果注册表和支撑材料中，不自动进入论文正文。
- 正文直接展开最终采用的模型，说明其与题意、数据、约束和验证相匹配的理由，并用真实证据表述优点、局限和适用边界；不写成候选模型排行榜或尝试过程日志。
- 只有题目、官方规则、用户明确要求，或读者无法在不看比较证据时理解模型选择，才用最少篇幅呈现必要比较；内部综合评分、全部候选参数和失败尝试不得机械搬入正文。
- “最优”“最佳”“显著优于”等措辞必须有相应证明或公平、稳定的比较证据。证据不足时使用“最终采用”“更适合当前任务”或条件化表述。

## 模型评价、引用与附录

- 优点用约束表达、误差下降、样本外表现或计算证据具体说明；不足指出数据、参数主观性、假设偏差、复杂度和泛化边界；推广说明替换变量、扩展约束、适用条件和新增数据。
- 非常规模型、核心算法、外部数据、经验参数、现实规律和特定评价方法首次使用时引用真实来源；正文编号与文后文献双向对应。
- 附录开头给出支撑材料清单，说明文件名、对应问题、用途、程序入口/工作表、主要输出和完整结果位置。完整代码放入统一附录或按竞赛要求作为独立支撑文件，正文只保留必要伪代码和关键公式。

## 个人交付偏好与完整性

黑色标题、图像不过密、表格三线表；摘要不超过一页；正文不设目录、不出现身份信息。当前交付优先 Word，具体版式和页数服从最新官方规则。公式输出、表格、年份格式、代码路径和AI披露执行 `user_delivery_contract.md`；完整性执行 `paper_integrity_gate.md`；语言修改执行 `academic_style_revision.md`。

## 证据链、段落职责与干净交付

- 正式写作前，对每个核心主张登记来源、可支持范围、对应模型/代码、结果 ID、图表或验证位置。来源不足时检索、改写为条件化陈述、删除或请求补充，不能用看似完整的数字、场景、机制、文献或占位标记填补。
- 每段先在内部确定唯一职责：主张、支撑证据、解释或限制、与前后文的衔接。输出只给自然正文，不泄露内部流程、检查表、证据等级、段落标签或协作提示。
- 观察与解释分开；实测结果、计划方案、假设、推断和建议分开。贡献只有在题目需求、模型模块、真实结果和验证之间可追溯时才写成完成式，其他情况使用条件边界或后续工作表述。
- 引用先核验存在性和可用信息层级。仅有书目信息时只作元数据级表述；无法核验时不写入参考文献。检索或全文访问受限时只使用用户已提供且可定位的资料，并在正文外说明限制。
- 润色只改善表达，不能静默强化、弱化或改变科学含义。发现原文主张无证据、结论越界或与结果冲突时，先退回责任阶段而不是以语言修饰掩盖。
