# 论文完整性统一门禁

本文件是写作与审核阶段的统一完整性规则源，其他 Skills 引用而不重复维护。

## 输入版本与增量检查

开始撰写或续写前确认当前题面、最终求解入口、结果注册表、图表清单、支撑材料、当届规则和已确认正文版本，不要求预先绑定论文绝对路径。用户说“下一部分”时，若已提供论文文件则重新读取该文件，否则依据当前对话中的已确认版本续写；上一部分版本不明时先确认最新版。

每次续写前检查：

1. 章节顺序、编号和信息归属是否连续，是否重复已有模型、结果或小结；
2. 摘要、正文、表格、图注与结果注册表的同一数字、单位和精度是否一致；
3. 新公式符号是否定义，停用符号和旧模型口径是否残留；
4. 图、表、公式是否已交叉引用；每个独立公式是否有唯一公式号，图、表、公式编号及题注是否连续；
5. 正文引用与参考文献是否双向对应；
6. 数据预处理叙述、数据清单、清洁基础数据、模型就绪数据、处理器、划分、代码、结果注册表、图表、附录和结论是否来自同一锁定数据血缘与最终运行；是否存在下游重新清洗、回读原始附件或旧数据版本残留；
7. 是否残留“此处插入、待补充、TODO”等编辑占位；对话交付中的“LaTeX源码”及单行代码是规定格式，平台长度限制下明确标注的交付范围和衔接提示也不作为论文占位错误；正式成稿文件不含这些对话辅助标签；
8. 当前修改是否导致结论越界、标题过细或页数预算失控；
9. 新生成或修改的正文是否已完成保真润色，并与初稿、语义锁和结果源反向核对，是否因润色改变数值、模型含义、因果方向、结论强度、适用范围或负面结果。
10. 摘要是否通过独立可读性检查：仅看摘要能否准确复述各问的方法、关键结果、结论和评价；正文中的核心结论、负面评价或适用边界是否在摘要中被遗漏或改变。
11. 是否逐项执行`paper_writing_revision_contract.md`：摘要首段和分问段、问题重述的现实问题与意义、问题分析的因素—数据—策略链、大而必要的假设、问题导向标题、通俗模型解释、公式来历与作用、数值求解说明以及面向现实且不重复结果的模型评价是否完整。

确定错误立即回退责任 Skill；语义无法自动判断的项目标记人工复核，不直接判错。

## 模型与验证专项门禁

- 每问直接回答题目要求，给出具体数值、方案或判断，并说明完整结果所在文件/工作表。
- 题目约束、求解设置和数据处理未混入模型假设；问题分析未提前展开公式和算法。
- 模型假设不是题面条件的改写清单；每项新增理想化都说明忽略机制、适用域及其验证或限制位置。
- 递进问题采用增量写法，前问公式不整套重抄；关键结构性结论具有推导、边界、反例、独立算法或文献证据。
- 模型建立与求解分开；搜索区间、步长、停止条件、求解状态和最优性措辞准确。
- 每个优化模型均完成“变量索引与单位—定义域与边界来源—标量目标—约束方向与量纲—重叠去重口径—罚项/权重依据”检查；集合并集、事件集合或向量本身不得冒充可优化标量。
- 每问至少一项针对核心风险的主验证；验证对象、方法、指标、结果和结论边界完整。可行性不等于稳健性，收敛不等于泛化。
- 人工阈值、最小规模、惩罚、相关系数、弹性和支持集有依据与敏感性；同一情景方案比较保留配对差值，置信区间按`evaluator_review_principles.md`的重采样适用条件检查；固定情景无抽样含义时报告范围并说明不适用。
- 对“稳定、减少重叠、均衡、效率、稳健、工程可行、可复核、显著改进”等高频结论，逐项执行`evidence_claim_discipline.md`的最低证据检查；证据不足时补证或降低措辞，不以模型评价段的自述代替验证。
- 关键措辞台账中的每项后果性条件均能追溯到变量、方程、约束、目标、情景、验证或明确阻断项；模型说明、实际代码和论文表述具有逐项映射，不存在论文有而代码无或代码改口径但符号与正文未传播的情况。

## 数字、公式、图表与支撑材料

- 符号表覆盖全部现用公式符号且无停用项；目标函数、产量/预测和收入/损失定义的索引粒度一致。
- 同一结果ID由未舍入原值统一格式化，差额、比例、增长率和百分比重新计算，基数、单位、年份、样本数和变量数一致。
- 数值比较明确分母和口径，区分“增加百分比”“增加若干倍”与“达到原来的若干倍”；摘要、正文、表图与结论中的派生量均由未舍入源值复算。
- 表格给精确值，图形给趋势/差异/分布，文字给解释，三者不完整重复；重要图按论文实际尺寸自审，重合曲线换用差值图等合适表达且不夸大。
- 每张结果表或结果图后回到题目要求，用正文说明“观察到什么、回答了什么、证据边界是什么”；不能由图表直接跳到下一问。每个关键结果均须能定位到结果ID、计算来源或原始统计，并完成对象、指标、单位、基准、含义和评价边界的结果解释闭环。
- 逐表检查占位符语义：任何结果单元格中的“—”都必须在该表表注中定义，且含义唯一；能够写成“无数据”“不适用”“未计算”或“无有效样本”时优先直接写明，不允许读者猜测“—”代表零值、缺失值还是不适用。
- 附录或支撑材料含“程序—问题—输入—输出文件/工作表—字段—关键参数—结果ID—约束审计”清单；最终入口、结果文件、图表、完整代码和工作表名称可相互追踪。

## 结构、表达与版式

- “问题重述”一级标题下依次设置“问题背景”“问题重述”两个二级标题；“问题分析”一级标题下按小问分别设置“问题一分析”“问题二分析”等二级标题，并按`paper_writing_revision_contract.md`完成附件写作合同审查。
- 标题层级原则上不超过三级；简单内容不拆标题；共用数据处理集中成章。
- 无教材式大段定义、无证据自评、流程套话、重复题意、重复小结和无分析价值图表。
- 题目与关键词具有区分度；摘要各问按`paper_writing_revision_contract.md`使用对应编号的“针对问题x，……”开头，各段长度相近且信息均衡，对话版已直接加粗少量核心信息，包含模型、方法、关键结果和结论，且不超过官方页限。
- 题目、摘要、关键词、正文、图表和参考文献中的对象、算法全称/缩写、指标与结论口径全局一致；首次出现使用可识别的规范名称，后续不得换名或省略到产生歧义。
- 参考文献真实、引用格式统一；DOCX/PDF无身份泄露；页数、正文起始页、页眉页码、表格跨页和AI披露符合最新规则。

## 自动审查与释放

有用户提供或明确要求生成的文件时，运行`../paper-review/scripts/audit_paper_integrity.py`初筛其支持的数字、符号、占位、引用、身份元数据、页数和编号；纯对话内容按相同适用项目核对正文、表格、图像和公式，不为运行文件审查器自动生成Word或PDF。脚本未检出不等于通过；用户或官方规则明确要求版式验收时，再检查相应目录、页码、页眉、跨页断裂和最终版式。

释放条件：阻断项为零，高风险问题闭环；按`evaluator_review_principles.md`记录缺陷及验收证据，不以主观评分阈值代替放行判断；最终入口、结果注册表、正文、图表和附录一致；正文已通过保真润色与反向语义核对。

## 证据主张与问题分级门禁

- 审核每个关键结论、外部事实、引用、经验参数和比较性语句是否有可定位来源，且表述强度未超过来源可支持范围。模型记忆、历史案例印象、检索标题和未经核验的摘要不能支撑具体机制、数值或因果解释。
- 引用核验区分“未找到”与“无法检索”。发现书目信息不一致、元数据被扩写为全文结论、或关键来源不可确认时，修正、降级、删除或列为待用户确认；不得把问题藏在论文正文的占位符中。
- 阻断项优先于任何语言、版式或美化事项：题意/数据口径冲突、无运行来源的数字、核心结果与代码不一致、结论被反证、数据泄漏、身份或官方格式失效均须先回退修复。审核报告中每项阻断和高风险问题都需给出直接证据位置、影响范围、责任 Skill 与复核动作。
- 终审前执行一次反向审视：检查是否仅保留支持性结果、是否遗漏失败情景或简单基准、是否将观察写成因果、是否将条件结论写成普遍结论。发现反证后更新所有受影响的摘要、正文、图表和附录。


## 自动数值初筛输入与覆盖

- `audit_paper_integrity.py`支持同结构JSON数值映射，或带`result_id`的结果记录（单条、数组或`results`容器均可）；记录按`result_id`及实际提供的`problem_id`、`metric`、`scenario_id`、`fold_id`组合识别，字段须在双方一致。多行CSV必须含`result_id`，单行宽表可按完整列名匹配。只支持可解析数字，不自动把百分号、千分位或单位文字猜成数值。
- `unit`、`version`、`data_version`、`model_version`、`processor_version`、`split_id`、`run_id`作为元数据核对，双方值不一致阻断，缺项报告未覆盖；注册项的`status`以`verified`/`published`或“已核验”/“已发布”表示已核验状态。无此元数据的旧式数值映射仅证明对应数值关系，版本与发布状态须另行审查。
- 检查报告及JSON中的`numeric_coverage`列出实际字段数、匹配数、未匹配项与状态。退出码0仅表示已输入范围未发现自动规则问题；1表示警告或未检查/部分覆盖；2表示阻断。正式发布所必需项缺失时，终审应阻断对应结论，不能因脚本未报阻断而算通过。图题启发式识别无法确定时按候选问题人工确认，不把普通正文引用当作确定的编号错误。
- 修改初筛或同步逻辑后运行`../paper-review/scripts/test_agent_repairs.py`的行为回归，并运行`../paper-review/scripts/validate_skill_suite.py`检查完整配置；两者分别证明脚本行为和静态结构，不替代真实赛题的科学核验。
