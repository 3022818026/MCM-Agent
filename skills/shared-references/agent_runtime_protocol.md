# 数学建模 Agent 运行时与恢复协议

本文件把自动化系统中可迁移的工程优点纳入数学建模通用工作流，不替代数据、模型、评价、写作或终审判断。

## 项目状态与检查点

- 阶段编号和名称统一取自`MATH_MODELING_AGENT_PROMPT_CHAIN.md`的1—13阶段；每轮按`competition_workflow.md`选择所需阶段。数据处理属于阶段1的专项工作，发布是阶段13验收后的状态，不另设阶段序列。状态使用待处理、进行中、阻断、已核验和已发布；另记未选择、不适用或复用证据，未选择不等于已核验。
- 维护项目状态文件，记录绑定路径、本轮需求、所选阶段及理由、复用证据版本、必要前置、停止点、当前阶段、数据/配置/运行ID、结果注册表、待更新产物、阻断项和最近有效检查点。
- 在数据口径、模型路线、最终运行、模型评价、正文和终审锁定后保存检查点。
- 恢复时先比较输入文件哈希和关键产物，不盲目沿用旧会话或压缩摘要；文件变化后从最早受影响阶段失效下游结果。

## 会话启动的规则版本变化清单

- 启动或恢复实际建模项目、上下文未保留规则正文，或权威目录有更新迹象时，核对当前Skills根目录和规则变化。按[rule_authority_index.md](rule_authority_index.md)确定本轮阅读范围；版本清单不要求加载全部专项正文。
- 使用[scripts/inventory_rule_versions.py](../scripts/inventory_rule_versions.py)扫描本套Skills的规则Markdown并比较先前清单。范围包含SKILL.md、目录AGENTS.md、共享参考和专项references，不包括assets、代码、UI配置及工作区外规则；不将其当作整个部署包的完整性证明，套件结构仍由现有校验器检查。
- 首次运行不传旧清单；之后显式传入已有记录。记录缺失、格式损坏或根目录不同须说明，不能悄悄回退旧副本或称为“规则未变”。清单中的新增、修改、移除与未变均只是文件状态，哈希不能证明当前会话已阅读、理解或执行。
- 对新增或修改且本轮适用的文件完整读取；未变但当前上下文未保留的必读文件也须读取。移除文件检查是否仍被入口引用；内容变化先评估影响，不机械重跑所有阶段。影响模型、验证或交付要求时更新活动规则卡，并将实际受影响产物标为待复核。
- 已有项目将清单保存到其内部记录目录，与当前阶段选择关联；纯咨询可只输出清单而不创建文件。脚本只在显式提供输出路径时落盘，禁止写入Skills安装目录；先前清单不能冒充当前会话阅读记录。

命令中的Python使用已解析的解释器，路径相对当前工作目录；省略输出参数只打印JSON：

    python <skills根目录>/scripts/inventory_rule_versions.py --root <skills根目录>
    python <skills根目录>/scripts/inventory_rule_versions.py --root <skills根目录> --previous <项目记录>/rule_versions.json --output <项目记录>/rule_versions.json

首次落盘仅指定--output。新会话是否已阅读由实际上下文核对，脚本不写“已读”或科学验收PASS。

## 输入完整性

- 快速预览只用于发现文件、页数、工作表、字段和解析风险；正式审查必须覆盖全部相关页、工作表、数据行、隐藏结构、注释和题目约束。
- 预览摘要不得替代原始附件。附件应存在但解析失败时立即阻断；只有题目明确授权时才能构造模拟数据，并与真实附件分开登记。
- 输入清单记录路径、类型、大小、修改时间、内容哈希、读取状态和解析器。

## 产物、环境与恢复

- 原始附件只读；代码、处理数据、结果、图表、论文、日志和检查点分目录保存。
- 维护产物清单，记录文件ID、路径、用途、生成入口、输入依赖、运行ID、状态和哈希。文件变化只触发待复核，不代表内容正确。
- 最终运行保存操作系统、语言/求解器版本、关键依赖、硬件、线程、随机流、运行命令和网络模式。
- 重要输出先写临时文件，校验后原子替换；覆盖前保留可追溯版本。

## 题型适用性与证据登记

每轮按十三阶段提示链判定哪些要求适用。涉及计算的任务必须保留真实代码、日志、运行ID和数值结果；无计算需求的纯理论任务以命名证明、推导、边界和独立复核记录形成证据登记，可将代码、训练划分、运行注册和无必要图件记为不适用，不能虚构运行或为满足清单强加算法。该适用性解释贯穿数据、设计、评价、写作、终审的输入与完成标准；不能把缺失本应存在的计算结果解释成理论例外。

## 自适应验证

- 数值迭代、微分方程和仿真重点检查步长、收敛与极限行为。
- 优化模型重点检查可行性、约束、最优性证据、扰动和计算规模。
- 统计与机器学习重点检查数据划分、泄漏、残差、置信区间、重复性和泛化。
- 机理估计重点将参数代回模型，重构可观测量并与附件比较。
- 同一 Agent 的重复自检不等于独立验证；根据核心风险选择验证，不机械要求所有题使用相同步长、折数或双算法。

## 联网、发布与安全

- 联网分为关闭、受限和开放模式。检索方法与适用条件，优先官方规则、原始论文、教材和官方文档；不搜索本题答案，不绕过题目数据限制。
- 最终入口统一生成结果注册表、逐样本/逐情景评价数据、图表数据和支撑材料清单；发布前完成适用的结构、格式和独立终审检查。仅使用八个数学建模Skills时不额外要求Word渲染中间件；同时调用文档专用Skill创建或编辑`.docx`时，执行其渲染与逐页检查门禁，当届官方模板仍是竞赛版式权威。
- 文件操作限制在用户明确给出的项目目录；未知路径先询问。规范化绝对路径并检查目录边界，不只做字符串前缀匹配。
- 不删除项目外文件，不明文保存凭据；沙箱或隔离不可用时停止或请求授权，不静默降级。

## 不吸收的做法

不得固定图数、公式数、模型数、假设数、交叉验证折数或流程图；不得把特定历史赛题变量和验证关系写入通用规则；不得用截断摘要替代附件、用自动模拟掩盖读取失败，或以单一 Agent 自检替代独立评价。

## 全程质量闭环触发

八个通用Skill每次生成或改动可交付内容前、后及发布前，均按`quality_gate_protocol.md`执行全程生成—审查—修复闭环。未通过项必须回到最早受影响阶段修复并重做受影响检查；真实阻断项保持阻断，不得用推测、旧产物或形式检查替代通过证据。
