# 全国大学生数学建模竞赛全程工作流

本文件规定从接收赛题到最终提交的统一流程。目标是形成模型正确、结构紧凑、结果可信、验证充分且可复现的竞赛论文；以高等级奖项标准要求过程，但不承诺获奖结果。

## 调用原则

每个阶段只设一个主 Skill。共享规则由主 Skill 内部读取，只有产物跨越专业边界时才转交，不要求用户同时调用整条 Skill 链。

| 当前任务 | 主 Skill | 转交条件 |
| --- | --- | --- |
| 全题统筹、跨阶段决策 | `modeling-scientist` | 进入具体数据、实现、评价或写作 |
| 审题、逐问拆解、路线设计 | `modeling-design` | 需要读取和处理真实附件 |
| 数据审查、清洗、特征与参数 | `data-preparation` | 数据口径改变导致路线重审 |
| 编码、调试、训练与求解 | `model-implementation` | 方案未锁定或需要独立评价 |
| 验证、敏感性与最终选择 | `model-evaluation` | 实现错误先退回实现 |
| 正文、摘要与表达修改 | `paper-writing` | 需要重算、重绘或改变模型 |
| 单独制作或修改论文图表 | `figure-generation` | 图表结果尚未核验 |
| 整稿与提交前独立终审 | `paper-review` | 按责任回退到对应 Skill |

正式写作期间由 `paper-writing` 做增量检查；`paper-review` 保持独立，用于阶段性整稿检查和提交前终审。

## 短指令意图补全与应急模式

- 用户只说“分析题目”“继续写”“优化模型”或“审查论文”时，先从四个轴补全当前任务：覆盖范围、所处阶段、所需产物和质量标准。能由已绑定项目、上下文和现有文件确定的内容直接继承；只有缺失信息会改变模型、数据口径、修改范围或交付格式时才询问。
- 意图补全只用于确定本轮边界，不得把候选方法、固定产物数量或历史案例结论当成用户要求。补全结果应落实为当前主Skill、输入清单、完成证据和下一检查点。
- 截止时间紧时进入风险优先的应急模式：先处理题意误读、附件缺失、硬约束、数据泄漏、不可复现、结论越界、数字不一致和匿名/格式否决项，再处理表达与美观。应急模式可以缩小候选范围和装饰性产物，但不能跳过数学正确性、结果真实性、核心验证和提交硬规则。

## 九阶段流程

1. **题型与交付识别**：逐问识别优化、预测、分类、聚类、评价、机理、微分方程、几何运动、图论路径、排队库存、随机模拟、多目标、统计推断或混合任务，建立“题目要求—附件字段—输出文件—完成证据”映射。
2. **问题关系识别**：判断各问独立、参数传递、推广、确定性到随机性、单目标到多目标、简化到复杂或建模—检验—应用等递进关系。
3. **信息归属与章节骨架**：为题意、数学转化、共用数据、变量、目标、约束、求解、结果、验证、评价和完整代码指定唯一主要位置；预先确定标题层级、流程图、页数预算和附录。
4. **验证预设计**：每问在建模前确定核心风险、主验证、必要辅助验证、需保存的中间结果、评价指标、图表和可支持的结论。
5. **数据、模型与计算**：完成数据审查、模型设计、实现和求解；代码、结果注册表、图表数据、结果文件和论文候选数字来自同一最终运行。
6. **逐问结果验证**：按预设协议执行，不把约束可行、数值收敛、样本外泛化或稳健性相互替代。
7. **竞赛化写作**：按“一问一条主线、一节一个功能、一段一个核心信息、一图一个分析目的”写作；正文回答为何建模、核心关系、如何求解、得到什么、为何可信及实际含义。
8. **信息密度压缩**：优先删除重复、无效标题、教材式定义和装饰图，把完整结果和长代码移入附录或支撑材料；不得删除核心公式、变量、关键参数、结果、模型理由和必要验证。
9. **一致性与终审**：检查数字、公式、单位、符号、图表、代码、引用、结果模板、匿名、AI披露和最终版式，完成修订后独立复核。

## 阶段释放与即时回退

- 关键事实、数据口径、模型路线和验证协议未稳定，不进入正式写作。
- 数据错误回退 `data-preparation`；路线、假设或关键机理回退 `modeling-design`；代码、约束或结果回退 `model-implementation`；泛化、风险或敏感性回退 `model-evaluation`；图表回退 `figure-generation`；结构和表达由 `paper-writing` 修订。
- 修正后重新运行受影响代码、更新结果注册表并复核全部下游产物；不得“先写完再补”。
- 用户要求“下一部分”时，先读取已绑定论文文件并执行增量审查；上一部分未保存时先确认最新版。

## 最终优先级

发生冲突时依次服从：数学与数据正确、不捏造、模型适配、关键结论有依据、验证针对性、数值一致、直接回答题目、结构清晰、正文精简、图表有效、语言专业、形式美观。形式和篇幅不能凌驾于核心模型与必要验证。
