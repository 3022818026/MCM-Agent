# 论文书写修改要求常驻合同

本文件固化用户明确要求并入数学建模 Skills 的《论文书写修改要求》，是八个通用 Skills 的常驻高优先级用户合同。它规定各阶段为论文写作保留什么证据，以及摘要、问题重述、问题分析、模型假设、模型建立与求解、模型评价的写作和终审标准。它不是当前赛题的事实、数据、模型或官方格式来源，不得用来补造缺失证据。

## 1. 优先级与适用边界

- 每次调用 `modeling-scientist`、`modeling-design`、`data-preparation`、`model-implementation`、`model-evaluation`、`figure-generation`、`paper-writing` 或 `paper-review` 时，必须完整读取本文件，并把当前阶段适用条款加入 `quality_gate_protocol.md` 规定的活动规则卡。
- 冲突依次按“用户当前任务中的最新明确要求—数学与数据正确性—当届官方规则与当前项目证据—本合同—其他通用写作建议—历史经验”处理。本合同的高优先级不允许覆盖数学正确性、真实数据、官方硬性规则或当前题目要求。
- 本合同中的篇章结构、信息内容和审查标准属于稳定用户偏好；`academic_style_revision.md`仍是语言润色与语义保真的最高权威。两者分工而非互相覆盖。
- 非写作阶段不得提前编造正文。其职责是形成可追溯的“论文证据交接”：数据来源、处理依据、方法链、公式来历与作用、核心结果、实际含义、局限和适用边界。证据尚未产生时明确标为待验证，不以顺畅叙述填补。
- 本文件保留附件要求的实质内容，但不把“约100字”“每问一段”等写成脱离官方模板和可读性的机械计数器；偏离时必须说明是当前用户新要求、官方规则、证据完整性或数学表达所必需，而不能因写作方便静默忽略。

## 2. 每次调用的跨阶段强制动作

| Skill | 当前阶段必须落实的合同动作 | 交给下游的最小证据 |
| --- | --- | --- |
| `modeling-scientist` | 在总路线中同时规划题目背景、逐问问题、数据与方法、核心结论、实际意义和最终评价的证据来源；不得把论文写作推迟为无来源的末端包装 | 逐问“背景—问题—数据—方法—结果—意义—边界”证据槽及责任阶段 |
| `modeling-design` | 逐问给出因素考虑、数据处理理由、方法为什么适用、需要哪些大假设、公式或机制依据、数值求解路线和可回答的结论类型 | 逐问分析链、模型标题候选、假设依据、验证卡和结论边界 |
| `data-preparation` | 保存可在摘要、问题重述和问题分析中准确说明的数据来源、选取范围、字段/样本、处理动作、理由、变化量和潜在偏差 | 数据来源说明、处理决策台账、样本/字段变化和允许写入论文的口径 |
| `model-implementation` | 登记模型是什么、公式来自何种定义/机理/推导、每个公式解决什么问题、采用何种求解方法以及结果对题目的直接含义 | 公式—代码—结果映射、数值求解设置、核心结果 ID、非专业读者可理解的结果释义 |
| `model-evaluation` | 把性能证据转化为贴近现实问题的优点、不足、未考虑因素、失效条件和推广边界；与结果细节分开 | 每问核心结论及证据、实际优缺点、未覆盖风险、可推广条件和通俗评价 |
| `figure-generation` | 每幅图服务某一问题、方法或结论，图题表达对象与论证任务，不以孤立指标名充当全部叙述；图后可回到题目给出结论 | 图号+图题、数据/结果来源、主要观察、对题目的回答和证据边界 |
| `paper-writing` | 逐项执行第3—8节的章节合同；缺少证据时回退责任 Skill，不用套话、虚构数字或虚构文献补齐 | 通过合同核对的成稿及可追溯结果、引用、公式和图表 |
| `paper-review` | 对第3—8节逐项给出证据锚点、通过/不通过/未覆盖状态、严重度、修复动作和责任 Skill；最终结论与未关闭问题一致 | “附件写作合同审查”结果和闭环后的复核证据 |

## 3. 摘要合同

### 3.1 总体结构

摘要整体按“背景+问题+解决方法+意义+针对每个问题的重要结论”组织。只看摘要，应能理解全文解决什么问题、基于哪些数据和方法、得到什么关键答案以及这些答案为何有意义。

### 3.2 第一段

- 用一句话交代综合性大背景，用一句话说明该背景下的具体问题，再简洁说明本文从什么方面提出解决方案及其实际意义。
- 第一段只承担总体概括，不提前堆放逐问结果、算法步骤或指标清单。
- 以约100字为优先目标，使读者迅速明白研究对象、问题、总体方案和意义；若官方模板、中文表达完整性或必要限定条件要求略有偏离，以清楚、准确和一页摘要约束为准。

### 3.3 分问段落

- 每个问题的摘要段必须以“针对问题x，……”开头，x替换为题目对应编号；中文编号示例为“针对问题一，……”“针对问题二，……”。正文不得保留字面占位符x，概述首段不使用这一分问开头。编号样式与题目及全文一致。
- 各问摘要段落长度应相近，方法、关键结果与结论的信息分配保持均衡。先压缩过长段中的次要过程，再检查过短段是否漏掉已有证据；不得为凑齐字数填充套话、虚构数字或删掉必要限定。差异确由题目复杂度或官方要求造成时，保留必要信息并在内部核对记录中说明，不设置机械的统一字数或差值阈值。
- 在对话中交付摘要时，直接使用Markdown加粗少量核心模型、关键定量结果、主要结论和评价证据，展示已经加粗的完整摘要；不得仅指出“哪些词应加粗”或输出未处理的纯文本。各问重点选择应均衡，不整段加粗，不加粗全部数字或“针对问题一”等连接性开头。明确要求正式文件时，其加粗服从官方模板与当前用户要求。

- 从第二段起，每个实际问题单独一段，按题目顺序写“该问小背景+解决方法+重要结论”。递进问题的小背景存在联系时，明确前后逻辑。
- 方法说明必须交代数据来源或选取范围，以及对数据采用了哪些处理和方法；不得只列模型名称。
- 结论只保留直接回答该问的核心发现和必要关键数字，例如最优方案效果、准确率、误差、关键阈值或具体答案；不得纯罗列全部指标。
- 长短句结合，使背景、方法、结论和意义像一个完整故事自然推进，但不得为叙事效果强化证据或省略负面边界。

## 4. 问题重述合同

- 在摘要第一段基础上深入展开，整体仍按“背景+问题+解决方法+意义”组织，但不得照抄摘要或题面。
- 背景需说明当前现实环境、具体遇到的困难，以及这些困难给人、组织或社会造成的实际不便；讨论必须具体，不能泛泛拔高。
- 背景之后直接说明解决这些问题的现实意义，落实到可观察的决策、效率、成本、风险、资源或实施价值。
- 再说明本文的总体措施：基于什么数据和方法，使用何种模型或策略，研究什么问题或求得什么方案。每个问题的具体要求与措施单独一段，保持问题之间的递进关系。

## 5. 问题分析合同

- 每个问题设置一个独立的主分析段，详细给出从问题条件到建模策略的分析过程；公式、图表或必要说明不替代该主分析段。
- 分析重点是因素考虑和数据处理：说明哪些因素必须纳入、为何纳入、如何转化为可观测量或约束，以及数据需要怎样处理才能支持该策略。
- 可以用真实案例或文献解释因素与方法依据，但文献必须真实、可查并直接支持当前表述；不能凭模型记忆或检索标题补写。
- 不得把“比较了若干模型并选择某模型”当成分析过程。必须说明涉及什么知识、题目结构或数据特征，如何由这些证据推出当前策略可用。
- 问题复杂到一个主分析段无法保持准确和可读时，只能在当前用户明确允许、官方格式要求或必要数学论证驱动下拆分，并保留一个清楚的主分析链；不得因模板习惯自动扩成多段。

## 6. 模型假设合同

- 只列与当前问题整体结构、可解性或主要简化直接相关的大假设，不机械枚举各种不可控因素、社会差异或常识性条件。
- 每项假设必须说明其作用、忽略的机制、适用边界及后续验证或局限位置；题面已给条件不得伪装成新增假设。
- 使用自然、具体、问题导向的表述，避免整齐但无信息的“AI式假设清单”。条目数量由问题需要决定，不设固定数目。

## 7. 模型建立与求解合同

- 关键计算步骤说明依据、实际做法或判据、产出及用途；复杂步骤可配必要公式或伪代码，简单步骤不机械扩写，不规定每步字数、公式数或图数。每个会支撑结论的步骤产出，都应在结果段报告或明确指向验证、附录或支撑记录，避免“声称做了却没有结果”。
- 区分解释模型为何成立与说明程序如何求解。展示足以复核的关键推导、中间量和近似依据，不抄写无关算法教材；共用处理按论证需要集中说明，后问明确继承、替换和新增项。独立问题允许不同方法，不为统一叙事虚构依赖。
- 每问结果段包含直接回应该问要求的回答句，再说明数值或理论结果的含义、证据和边界。全文标题覆盖实际研究范围；理论或建议型任务以已证明结论、适用条件或具体建议回答，不为摘要量化而虚构数字。


- 标题优先展示该节的具体分析方法、可回答的结论或取得的成果，不使用脱离问题语境的单个指标术语充当标题。
- 模型、求解过程、结果和结论始终扣紧背景、问题和各问之间的联系。不得为了展示算法、公式或数据结果而脱离题目任务。
- 对模型和结果的解释必须具体，使不了解该模型的读者也能明白：模型描述什么关系、输入和输出是什么、结果代表什么、最终回答了什么。
- 每个核心公式说明来历和作用：来自定义、题面关系、守恒/机理、统计假设、优化目标或已有可靠方法中的哪一种，以及它在当前问题中解决什么。公式存在不等于解释完成。
- 对数据驱动量、无可靠闭式解的积分/方程或必须离散求解的问题，优先采用可复现的数值积分、数值优化、迭代或仿真方法，并记录算法、离散方式、容差、收敛和误差检查。若解析解正确、可验证且更清楚，不得为了形式强行改成数值法；数学与数据正确性始终优先。

## 8. 模型评价合同

- 改进针对已识别不足说明具体机制，区分已实现且验证的改进与尚未实施的方向；前者给出可追踪增益证据，后者用条件式说明所需验证，不伪装为已获得提升，也不强制编出量化收益。


- 回到现实背景和问题本身，说明模型在实际使用中的优点、不足、未考虑周到之处、失效条件以及未来可推广或应用的方向。
- 评价使用准确、易懂、面向实际决策的语言；必要专业术语首次出现时给出通俗解释，不以术语密度代替评价深度。
- 不在模型评价中重复结果部分的具体数据、逐指标排名或求解细节。数据表现与模型输出留在结果和验证章节，评价关注这些证据意味着什么、何时可用、何时不可靠。
- 优点和推广必须有证据或明确条件；不足不能只写空泛的“数据有限、模型有待改进”。

## 9. 写作与终审门禁

### 9.1 写作前

为摘要和第4—8节建立事实表，逐项绑定题面位置、数据来源、处理记录、模型/公式、结果 ID、验证、图表和引用。缺少证据的项目回退责任 Skill，不在正文中放置待补占位符。

### 9.2 写作后

逐项检查：摘要第一段是否完成背景—问题—方案—意义；是否每问一段、以“针对问题x，……”的对应编号开头且各段长度相近，并包含小背景、数据/方法和核心结论；对话交付是否已直接加粗核心信息且没有整段加粗；问题重述是否具体说明现实不便与实际意义；问题分析是否给出因素—数据—策略推导；假设是否少而关键；建模求解是否有问题导向标题、通俗模型解释、公式来历与作用、适当数值求解说明；模型评价是否回到现实且不与结果段混写。随后再执行语义锁、证据、编号、引用和版式门禁。

### 9.3 最终论文审查

- 沿“题目要求—模型/证明—求解或推导—结果—正文回答句—适用的摘要/结论”逐问核对；缺失证据回退责任阶段。每项审核记录正文位置到来源位置或结果 ID 的双向锚点，而非仅写“已检查”。
- 状态分别登记通过、未通过、未检查和不适用；未检查说明缺口，不适用说明题型或交付依据。脚本未覆盖、无法定位或未实际执行的项目不能算通过；机械检查通过与科学核验通过分别报告。


- `paper-review`必须设置独立的“附件写作合同审查”，覆盖第3—8节全部条款，不能用抽样段落代替全文检查。
- 每项发现给出精确页码、标题、段落首句、表图公式号或其他可定位证据；区分“未通过”和“材料不足未覆盖”。
- 虚构或不可核验的数据、文献、公式来源，核心结论无结果来源，或写作掩盖模型/数据错误，属于阻断项。
- 摘要缺少分问方法或核心结论、问题重述泛泛而谈、问题分析只列模型、假设成为AI式无关清单、结果脱离问题、核心公式无来历/作用、评价重复结果或没有实际边界，至少属于高风险项，发布前必须闭环。
- 约100字、长短句节奏和标题措辞的轻微偏差若不损害合同功能，通常作为改进项；若导致读者无法理解问题、方法或结论，则升级为高风险项。

## 10. 完成标准

只有八个 Skills 的活动规则卡均能定位本阶段适用条款及交接证据，`paper-writing`逐项满足第3—8节，`paper-review`完成第9.3节的全文审查且阻断项、高风险项已经闭环，才可声明该论文满足本合同。任何自动脚本通过只能证明其覆盖的机械项目，不能替代内容和论证的人工终审。
