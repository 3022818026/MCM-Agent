# 真实赛题学习闭环

所有数学建模 Skills 在处理真实赛题时使用本闭环。目标是让 Agent 随项目推进改进工作方式，而不是记忆并套用当前题目的答案。

## 记录格式

每次出现有效反馈、运行失败、审计异常或论文返工时，记录：

1. 场景：发生在哪个题目、阶段、文件或输出中；
2. 原做法：当时采用了什么方法；
3. 暴露问题：用户反馈或独立检查发现了什么；
4. 根因：格式、口径、数据、模型、代码、验证还是授权边界；
5. 修正：实际采取的修改；
6. 复核：通过什么运行、审计或视觉检查确认；
7. 迁移范围：通用规则或仅限当前项目。

## 从真实训练题中提炼的通用经验

- 论文正文不能放入导致公式失去渲染的整体文字容器。正文正常输出；大公式单独渲染，并紧跟可复制的 LaTeX 代码。
- Word 不能稳定识别用空格模拟的表格。需要表格时输出真实表格；正式交付使用真实 Word 表格对象和三线表边框。
- 图表默认采用单图独立输出：能分别承担结论或正文引用的内容不拼接；只有必须同尺度即时对照且合并后仍清晰时才使用子图。图像密度过高时立即拆图、增加留白，并保持克制配色。
- 导出舍入可能导致约束违反。容差须根据当前变量单位、导出精度与求解设置确定；修复须保护全部联动约束并重新完整审计，不直接套用历史题目的单位或容差。
- 同一量在不同实体、时段或来源组具有不同参数时，按真实索引核算；未经等价性证明，不以整体均值替代分组参数。
- 受限候选支持集和非零 MIP gap 只能支持条件优化结论，不能宣称严格全局最优。
- 相关性调整方案可能在样本外指标上不如原方案。必须保留负面结果，必要时把原方案作为基础策略、调整方案作为备选，而不是强行声称改进。
- 随机种子用于复现，但正文没有必要写日期式长种子；新代码使用普通编号，并用独立随机流区分求解情景与检验情景。
- 用户明确给出代码路径前不得修改文件；给出路径后只修改该路径及明确的可追溯镜像。
- Word转换失败通常来自多行源码、复杂环境、长段中文条件或未经验证的命令。独立公式应提供一整行可直接粘贴的Word公式输入代码，长中文条件移到公式外，并在实际Word公式框中测试；不得笼统禁用`\left`、`\right`等标准命令。
- 两个分位数或阈值非常接近时，不在相邻竖线上放置旋转数值标签；改用固定位置的信息框，并用颜色和线型区分竖线。

## 阶段复盘

每完成数据审查、模型选择、模型实现、模型评价、绘图、正文或摘要中的一个阶段：

1. 检查是否出现新错误或用户纠正；
2. 更新当前项目规则；
3. 提取真正可迁移的通用经验；
4. 核验规则之间是否冲突；
5. 在下一阶段执行前读取最新规则。

不得把当前赛题的作物编号、参数、收益数值、图表编号和文件路径作为其他赛题默认值。
## 规则迁移

已验证的跨题型规则分别迁移到 `competition_workflow.md`、`paper_integrity_gate.md`、`academic_style_revision.md` 和 `evaluator_review_principles.md`。本文件只保留学习闭环，不重复维护规则正文。

## 本轮协作提炼的通用教训

- 模型从单一价格扩展到价格来源组后，只改收入约束不够；符号表、目标函数、代码字段、结果和正文必须同步传播，旧口径残留应作为阻断错误。
- 人工设定的阈值、最小规模和偏好惩罚会改变可行域或最优解结构，必须在设计阶段登记依据，在评价阶段做敏感性；纯次级偏好优先使用词典序优化。
- 同一批情景上的两个方案即使总体收益接近，也应保存逐情景配对差值，按`evaluator_review_principles.md`确定区间是否适用或改报情景范围，不能根据分别舍入后的均值作结论。
- 一个结果只能从同一未舍入源按统一规则显示。末位小数不一致反映结果传播失控，不能视作无关紧要的排版差异。
- 两条曲线重合时，继续叠画通常不能完成比较任务。应生成逐情景差值分布等候选图并在论文实际尺寸下迭代自审；若差异确实很小，应忠实呈现证据不足而非放大视觉差异。
